# Установка indexd Smart Autopilot и s3d на Windows

Это руководство описывает нативную установку без Docker: сначала PostgreSQL 18, затем indexd Smart Autopilot, после него s3d Smart Autopilot и, при желании, rclone, который превращает хранилище в обычный диск в проводнике. Шаги проверены на живой установке; там, где что-то может пойти не так, есть пояснения.

В примерах используются следующие пути и адреса. Их можно менять, но тогда меняйте последовательно во всех шагах.

| Что | Путь / адрес |
|---|---|
| indexd (программа и конфиг) | `C:\IndexD` |
| Данные indexd | `D:\IndexD\data` |
| s3d (программа и конфиг) | `C:\S3D` |
| Данные s3d (буфер загрузок) | `D:\S3D\data` |
| Порты indexd | admin `9980`, синхронизатор `9981`, application `9982` |
| Порты s3d | S3 `8000`, admin `8001` |

## Требования для установки

- Windows 10 или 11, 64-битная.
- PostgreSQL 18 для Windows.
- Не менее 60 ГБ свободного места без учёта базы блокчейна (consensus); сама она сейчас занимает около 89 ГБ.
- Место под буфер s3d: по умолчанию до 10 ГиБ.
- Siacoin на кошельке indexd для оплаты контрактов.
- Бинарники `indexd.exe` и `s3d.exe` из раздела [Releases](https://github.com/MainQuestion/indexd-smart-autopilot/releases).

## 1. Установка PostgreSQL 18

indexd хранит все свои данные — хосты, контракты, слэбы, настройки — в PostgreSQL, поэтому начинаем с него.

1. Скачайте установщик PostgreSQL 18 для Windows: https://www.postgresql.org/download/windows/ (сборка EDB).
2. В установщике выберите компоненты **PostgreSQL Server** и **Command Line Tools**; pgAdmin и Stack Builder не понадобятся.
3. Задайте пароль суперпользователя `postgres` и запишите его — он ещё пригодится.
4. Оставьте порт **5432**.

Чтобы убедиться, что всё работает, откройте новое окно PowerShell:

```powershell
Get-Service *postgres* | Select-Object Name, Status
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" --version
```

Служба `postgresql-x64-18` должна быть в состоянии `Running`, а `psql` должен сообщить версию 18.x.

## 2. Пользователь и база для indexd

indexd работает под собственным пользователем базы данных. Придумайте для него **отдельный** пароль — не тот, что у `postgres`:

```powershell
$psql = "C:\Program Files\PostgreSQL\18\bin\psql.exe"
$env:PGPASSWORD = "<пароль postgres>"
& $psql -U postgres -h localhost -c "CREATE ROLE indexd WITH LOGIN PASSWORD '<пароль indexd>';"
& $psql -U postgres -h localhost -c "CREATE DATABASE indexd OWNER indexd;"
$env:PGPASSWORD = "<пароль indexd>"
& $psql -U indexd -h localhost -d indexd -c "SELECT current_user, current_database();"
Remove-Item Env:PGPASSWORD
```

Последняя команда должна вернуть строку `indexd | indexd` — значит, пользователь создан и может войти в свою базу. Если русские слова в выводе выглядят как `ёЄЁюър`, не беспокойтесь: это лишь кодировка консоли.

## 3. Ограничение доступа к PostgreSQL

Установщик EDB нередко разрешает подключения к PostgreSQL со всех сетевых интерфейсов. indexd работает на том же компьютере, так что сервер базы лучше закрыть от сети. Выполните в PowerShell **от имени администратора**:

```powershell
$env:PGPASSWORD = "<пароль postgres>"
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -h localhost -c "ALTER SYSTEM SET listen_addresses = 'localhost';"
Restart-Service postgresql-x64-18
Remove-Item Env:PGPASSWORD
netstat -ano | Select-String ':5432'
```

После перезапуска в выводе `netstat` должны остаться только `127.0.0.1:5432` и `[::1]:5432`.

## 4. Размещение indexd

Создайте папки и положите в `C:\IndexD` файл `indexd.exe` из релиза:

```powershell
New-Item -ItemType Directory -Path C:\IndexD, D:\IndexD\data -Force | Out-Null
```

Конфиг удобно держать рядом с программой. Сообщите indexd, где он лежит:

```powershell
[Environment]::SetEnvironmentVariable('INDEXD_CONFIG_FILE', 'C:\IndexD\indexd.yml', 'User')
$env:INDEXD_CONFIG_FILE = 'C:\IndexD\indexd.yml'
```

> Папку данных задайте в мастере настройки (следующий шаг) и **не** задавайте одновременно переменную `INDEXD_DATA_DIR`. Переменная окружения важнее конфига, и путь из конфига будет молча проигнорирован.

## 5. Первичная настройка

Мастер настройки задаст несколько вопросов и создаст `indexd.yml`:

```powershell
cd C:\IndexD
.\indexd.exe config
```

| Вопрос мастера | Что ответить |
|---|---|
| Data directory | `D:\IndexD\data` |
| Recovery phrase (кошелёк) | Сгенерировать новую и записать на бумагу. Не используйте seed другого узла |
| Admin API password | Придумать — это пароль входа в веб-интерфейс |
| Application API advertise URL | `http://localhost:9982` — адрес, по которому к indexd будут подключаться приложения на этом компьютере |
| Admin API Address | `127.0.0.1:9980` — обязательно вместе с адресом: просто `9980` мастер не примет |
| Application API Address | `127.0.0.1:9982` |
| Database user / name | `indexd` / `indexd` |
| Database password | Пароль **пользователя indexd**. Если по ошибке ввести пароль `postgres`, indexd не запустится с ошибкой `SQLSTATE 28P01` |
| SSL mode | `disable` — локальный PostgreSQL работает без сертификата, и `verify-full` к нему не подключится |

Seed кошелька хранится в `indexd.yml` открытым текстом. Не выкладывайте этот файл и не синхронизируйте его в облако.

Проверить, что получилось, не показывая секретов, можно так:

```powershell
Get-Content C:\IndexD\indexd.yml | Select-String -NotMatch 'password|seed|recoveryPhrase|mnemonic|key:'
```

## 6. Ускорение синхронизации (по желанию)

Полная синхронизация блокчейна с нуля занимает много часов. Её можно сократить, подложив официальный снимок базы цепи (bootstrap):

1. Если indexd уже запускался, остановите его клавишами **Ctrl+C** и дождитесь сообщения `shutdown complete`.
2. Распакуйте снимок и, если на странице загрузки указана контрольная сумма SHA-256, сверьте её.
3. Посмотрите, как называется файл базы цепи в папке данных (`Get-ChildItem D:\IndexD\data`), переименуйте его, например, в `consensus.db.old` и положите снимок под прежним именем.

Если снимок лежит на другом диске, вместо копирования можно сделать символическую ссылку (cmd от имени администратора):

```cmd
mklink "D:\IndexD\data\consensus.db" "X:\путь\к\снимку\consensus.db"
```

> Один файл базы цепи может использовать только один узел. Не ссылайтесь на базу, которую уже открыла другая программа.

## 7. Первый запуск

```powershell
cd C:\IndexD
.\indexd.exe
```

Окно PowerShell остаётся занятым, пока indexd работает. В логе вы увидите версию (`INFO indexd {"version": …}`), подключение к PostgreSQL, применение миграций схемы (`migration complete`, `fork migration complete`) и, наконец, `node started`. Строка `waiting for wallet to be scanned` означает, что indexd догоняет цепь, — это нормально.

Веб-интерфейс откроется сам по адресу http://127.0.0.1:9980.

Чего ожидать в первые часы:

- **Список хостов поначалу пуст.** Хосты появляются по мере сканирования, а страница по умолчанию показывает только пригодные (usable).
- **Сообщение `indexer is offline, skipping scans`**, появившееся один раз, — признак кратковременного обрыва сети. Если оно повторяется, проверьте, что с компьютера доступны `1.1.1.1:443`, `www.google.com:443` и `www.amazon.com:443`: по ним indexd проверяет, есть ли у него интернет.
- **Ваш собственный хост в той же локальной сети может не сканироваться.** Для этого роутер должен поддерживать NAT loopback; indexd здесь ни при чём.
- **Uptime новых хостов начинается с 0.9 — ровно с порога пригодности.** На свежей установке один пропущенный скан выбивает хост из пула примерно на неделю. Прежде чем включать систему, дайте indexd несколько дней накопить историю.

## 8. Начальные настройки

Пока система выключена, задайте основные параметры:

1. **Configuration → Pricing.** Лимиты цен хранения, загрузки и скачивания (их можно привязать к доллару). Ставьте их с запасом над желаемыми ценами: новые контракты заключаются, только если цена хоста не выше буфера — по умолчанию 80 % лимита. **Min collateral** не ставьте вплотную к залогу дешёвых хостов: при привязке к доллару небольшое движение курса может сделать хост «ниже минимума», а это блокировка и перенос всех его данных.
2. **Configuration → Contracts.** **Wanted contracts** — не меньше общего числа шардов (N) схемы, которую будет использовать s3d, и лучше с запасом.
3. **Configuration → Placement.** Буфер цены для новых контрактов, минимальное расстояние между хостами (учтите, что GeoIP определяет местоположение лишь с точностью до города), радиус и точка отсчёта.
4. **Scoring.** Режим Smart: `Shadow` только записывает в лог, что сделала бы пауза, `Active` при превышении цены ставит хост на паузу вместо блокировки. Здесь же — лимиты скорости миграций и политика избыточности, если нужна схема ниже стандартной.
5. **Hosts → Candidates.** Посмотрите, каких хостов indexd выберет при текущих настройках и почему отсеяны остальные.
6. **Wallet.** Пополните кошелёк по указанному там адресу.
7. Включите систему переключателем **System is currently disabled**.

Через несколько минут на странице Contracts появятся первые контракты, а в логе — строка `filtered new contract candidates` со сводкой отбора.

## 9. s3d

s3d — это S3-совместимый шлюз: программы вроде rclone, Cyberduck или AWS CLI работают с ним как с обычным S3, а он шифрует данные, кодирует их и раскладывает по хостам, с которыми у indexd есть контракты.

### 9.1 Размещение

Положите `s3d.exe` из релиза в `C:\S3D` и подготовьте папки:

```powershell
New-Item -ItemType Directory -Path C:\S3D, D:\S3D\data -Force | Out-Null
[Environment]::SetEnvironmentVariable('S3D_CONFIG_FILE', 'C:\S3D\s3d.yml', 'User')
$env:S3D_CONFIG_FILE = 'C:\S3D\s3d.yml'
```

### 9.2 Ключ подключения приложения

Приложение может подключиться к indexd только по ключу, который выдал владелец индексатора. В веб-интерфейсе indexd откройте раздел **Keys** и создайте **app connect key**. Он понадобится через минуту — в поле «App password».

### 9.3 Регистрация s3d в indexd

```powershell
cd C:\S3D
.\s3d.exe login
```

- **Data directory** — `D:\S3D\data`.
- **Адреса** — S3 на `127.0.0.1:8000` (или `0.0.0.0:8000`, если нужен доступ из локальной сети), admin на `127.0.0.1:8001`. Пароль admin обязателен.
- **Indexer URL** — `http://localhost:9982`. По умолчанию там стоит `https://sia.storage`, то есть чужой индексатор.
- **Recovery phrase** — оставьте пустой, s3d сгенерирует новую. Обязательно запишите её: без неё данные невозможно расшифровать.
- s3d выведет ссылку вида `…/auth/connect/…`. Откройте её в браузере, введите app connect key и нажмите **Accept**. Запрос подключения действует недолго, поэтому ключ лучше создать заранее и подтвердить сразу.

### 9.4 Пользователь и S3-ключи

```powershell
.\s3d.exe users create <имя>
.\s3d.exe keys create <имя>
```

Вторая команда выдаст Access Key и Secret Key. Secret Key показывается **только один раз** — сохраните его в менеджер паролей.

### 9.5 Схема избыточности

В `C:\S3D\s3d.yml`, в разделе `sia`:

```yaml
    dataShards: 10      # K — шарды с данными
    parityShards: 20    # шарды чётности; всего N = K + parityShards
```

По умолчанию используется 10-of-30. Минимально допустимая схема для K = 10 — `parityShards: 15` (10-of-25). Схемы ниже стандарта, например 3-of-5, принимаются только при включённой пользовательской политике избыточности в indexd (**Scoring → Redundancy**). И помните: для каждого слэба нужно N разных хостов, пригодных для загрузки.

### 9.6 Запуск

```powershell
cd C:\S3D
.\s3d.exe
```

В логе появятся версия, строка `erasure coding scheme accepted` с принятой схемой, `indexer transfer limits` и `server started`. Состояние загрузок удобно смотреть из второго окна командой `.\s3d.exe status`. Admin API s3d в браузере не откроется — он рассчитан на программы; используйте `s3d status` или `curl.exe -u ":<пароль>" http://127.0.0.1:8001/stats/uploads`.

### 9.7 Доступ из локальной сети

Если S3 слушает `0.0.0.0:8000`, разрешите входящие подключения в брандмауэре. Сеть должна быть помечена как **частная** (`Get-NetConnectionProfile` → `NetworkCategory: Private`). PowerShell от имени администратора:

```powershell
New-NetFirewallRule -DisplayName "s3d S3 API (LAN)" -Direction Inbound -Protocol TCP -LocalPort 8000 -Profile Private -Action Allow
```

Не пробрасывайте этот порт в интернет: S3 работает по обычному HTTP, без шифрования.

## 10. rclone: хранилище как диск в проводнике (по желанию)

1. Установите драйвер файловых систем WinFsp: `winget install WinFsp.WinFsp`. Без него rclone не сможет смонтировать диск.
2. Создайте подключение (`rclone config` или веб-интерфейс rclone): тип **S3**, provider **Other**, ключи из шага 9.4, endpoint `http://127.0.0.1:8000` (или IP компьютера с s3d), region `us-east-1`, `force_path_style = true`. Если хотите видеть пустые папки, включите `directory_markers = true`.
3. Имена бакетов могут состоять только из строчных латинских букв, цифр и дефиса; подчёркивание не допускается.
4. Монтируйте диск с **полным кешем**, иначе программы вроде Total Commander будут получать ошибки записи:

   ```powershell
   rclone.exe mount "<подключение>:" S: --vfs-cache-mode full --network-mode --cache-dir D:\rclone\cache
   ```

   То же можно сделать через новый веб-интерфейс rclone: запустите `rclone.exe gui --addr 127.0.0.1:5580 --api-addr 127.0.0.1:5572 --user gui --pass <пароль> --cache-dir D:\rclone\cache` и смонтируйте диск через его API с параметром `vfsOpt='{"CacheMode":"full"}'`.

Несколько особенностей S3, которые поначалу удивляют:

- **Папок в S3 не существует.** «Папка» — это лишь общее начало имён файлов, поэтому пустая папка не видна, пока в неё не положить файл (или пока не включён `directory_markers`).
- **Перемещение — это копирование и удаление.** Для больших файлов это может означать скачивание данных из сети Sia.
- **Мелкие файлы не уходят сразу.** s3d копит их в буфере, пока не наберётся целый слэб. Отправить всё немедленно можно командой `s3d flush`.

## 11. Что хранить отдельно

Сохраните в надёжном месте, не только на этом компьютере:

- seed кошелька indexd;
- recovery phrase s3d;
- S3-ключи пользователей;
- регулярные дампы базы indexd:
  ```powershell
  & "C:\Program Files\PostgreSQL\18\bin\pg_dump.exe" -U postgres -h 127.0.0.1 -Fc -f E:\Backup_indexd\indexd-<дата>.dump indexd
  ```
- копии папки `D:\S3D\data`.

## 12. Обновление

1. Остановите s3d, затем indexd (**Ctrl+C** в их окнах).
2. Сделайте дамп базы: миграции схемы при обновлении необратимы, откатиться можно только из дампа.
3. Замените `indexd.exe`, запустите его и убедитесь, что в логе новая версия и `fork migration complete`.
4. Замените `s3d.exe` (если вместе с релизом обновляется и версия upstream s3d, сначала скопируйте `D:\S3D\data`) и запустите.
5. Обновите страницу веб-интерфейса клавишами **Ctrl+Shift+R**.

## 13. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| indexd не запускается с `SQLSTATE 28P01` | В `indexd.yml` неверный пароль базы — чаще всего введён пароль `postgres` вместо пароля `indexd` |
| Мастер пишет `missing port in address` | Адрес нужно вводить вместе с хостом: `127.0.0.1:9980` |
| Свой хост в списке без цен и координат | indexd в той же локальной сети, роутер не поддерживает NAT loopback |
| Хост выпал из пула после отключения электричества | Uptime опустился ниже 0.9; хост вернётся примерно через неделю стабильной работы |
| Хост заблокирован с причиной `Collateral` | Залог хоста ниже минимума — часто из-за курса при привязке к доллару |
| `connection request expired` при `s3d login` | Создайте ключ подключения заранее и подтвердите запрос сразу |
| Admin API s3d в браузере отвечает `Unauthorized` | Браузер не передаёт пароль; используйте `s3d status` или `curl.exe -u` |
| `InvalidBucketName` при создании бакета | В имени бакета недопустимо подчёркивание |
| Ошибки записи на смонтированный диск | Диск смонтирован без `--vfs-cache-mode full` |
| Разделы интерфейса пропадают при переходах между меню | Старая версия — обновитесь до последнего релиза |
