# Установка и обновление indexd Smart Autopilot в Docker

В этом варианте indexd работает в двух контейнерах: PostgreSQL 18 и сам indexd из готового образа. Исходники, Go и сборка не нужны: установка и обновление сводятся к нескольким командам `docker compose`. Образ собран под Linux (`linux/amd64`) и занимает около 58 МБ.

Образ содержит только indexd. Шлюз s3d в Docker пока не поставляется: его по-прежнему устанавливают отдельно (см. [инструкцию для Windows](INSTALL-windows.md), раздел 9) и подключают к indexd по адресу из шага 1.4.

Образ лежит в реестре GitHub: `ghcr.io/mainquestion/indexd-smart-autopilot:<версия>`. Версия образа — это версия upstream и короткий хеш коммита форка, например `v0.2.0-alpha.1`. Список версий смотрите в разделе Releases репозитория.

## Требования

- Docker Desktop (Windows, режим WSL2) или Docker Engine в Linux, Docker Compose v2.
- Около 90 ГБ под базу блокчейна и не менее 60 ГБ свободного места сверх неё. Docker Desktop хранит тома внутри собственного виртуального диска; если системный диск небольшой, перенесите этот диск в Docker Desktop: **Settings → Resources → Advanced → Disk image location**.
- Siacoin на кошельке indexd для оплаты контрактов.
- Файлы `docker-compose.yml` и `.env.example` из папки `docker` репозитория.

## 1. Установка с нуля

### 1.1 Подготовка

Создайте пустую папку, положите в неё `docker-compose.yml` и `.env.example`, затем скопируйте пример настроек:

```powershell
Copy-Item .env.example .env
notepad .env
```

В `.env` два обязательных значения: `POSTGRES_PASSWORD` — пароль базы данных (придумайте длинный) и `INDEXD_VERSION` — версия образа. Готовых значений по умолчанию нет, пока вы их не зададите, compose откажется запускаться. Файл `.env` содержит пароль, не выкладывайте его и не синхронизируйте в облако.

Папки с данными создавать не нужно: compose использует **именованные тома** `indexd-data` и `postgres-data`, и Docker размещает их сам.

> Не заменяйте именованные тома папками Windows (вида `D:\...:/data`). Когда мы пробовали так, база блокчейна на проброшенной папке повредилась (`panic: page … already freed`). Причина не доказана, но именованные тома надёжнее: данные лежат в родной файловой системе Linux внутри WSL2.

### 1.2 Скачивание образов

```powershell
docker compose pull
```

### 1.3 Recovery phrase

```powershell
docker compose run --rm indexd seed
```

Команда выдаёт новую recovery phrase кошелька. Запишите её на бумагу и не используйте фразу другого узла. Без неё к деньгам и контрактам доступа не будет.

### 1.4 Мастер настройки

```powershell
docker compose run --rm -it indexd config
```

| Вопрос мастера | Что ответить |
|---|---|
| Recovery phrase | Фраза из предыдущего шага |
| Admin API password | Придумать — это пароль входа в веб-интерфейс |
| Application API advertise URL | `http://localhost:9982` — адрес, по которому приложения на этом компьютере будут подключаться к indexd (s3d, запущенный на этом же компьютере) |
| Database host / port | `postgres` / `5432` — имя контейнера с базой |
| Database user / name | `indexd` / `indexd` |
| Database password | Тот же, что `POSTGRES_PASSWORD` в `.env` |
| SSL mode | `disable` — база в соседнем контейнере и наружу не публикуется |

Адреса прослушивания остаются такими, какие предлагает мастер: контейнер сам слушает на `:9980` (admin), `:9981` (синхронизатор) и `:9982` (application), а наружу эти порты публикует compose.

Конфиг сохраняется в томе `indexd-data` (`/data/indexd.yml`) и содержит seed в открытом виде. Не копируйте его в публичные места.

### 1.5 Запуск и проверка

```powershell
docker compose up -d
docker compose logs -f indexd
```

В логе появятся версия образа, подключение к PostgreSQL, миграции (`migration complete`, `fork migration complete`) и `node started`. Выход из просмотра лога — **Ctrl+C**, на работу узла он не влияет.

Проверка версии:

```powershell
curl.exe -s -u ":<пароль admin>" http://127.0.0.1:9980/api/state
```

В ответе должны быть ваша версия и `"os":"linux"`. Веб-интерфейс открывается по адресу http://127.0.0.1:9980.

Сначала indexd синхронизирует блокчейн, это занимает много часов. Пока `synced` не станет `true`, а `scanHeight` не догонит `syncHeight`, контракты не формируются (в логе `waiting for wallet to be scanned`).

### 1.6 Что дальше

Начальные настройки (цены, Wanted contracts, Placement, Scoring) такие же, как при установке на Windows: раздел 8 [той инструкции](INSTALL-windows.md).

### Порты

| Порт | Назначение | Доступность по умолчанию |
|---|---|---|
| 9980 | Admin API и веб-интерфейс | только `127.0.0.1` |
| 9981 | Синхронизатор (связь с другими узлами) | все интерфейсы: иначе узел принимает только исходящие соединения |
| 9982 | Application API (для s3d и других приложений) | только `127.0.0.1` |

Порты хоста можно изменить в `.env` (`INDEXD_ADMIN_PORT`, `INDEXD_SYNCER_PORT`, `INDEXD_APP_PORT`). Открывать admin-порт в сеть не рекомендуется: через него управляется кошелёк.

## 2. Обновление до новой версии форка

Миграции схемы базы данных форка применяются вперёд и **не откатываются**. Вернуться на прежнюю версию можно только из дампа, поэтому дамп делается всегда.

1. **Дамп базы.** Он делается внутри контейнера и копируется наружу. Перенаправление `>` в PowerShell портит двоичные файлы, поэтому им не пользуйтесь:

   ```powershell
   $d = Get-Date -Format 'yyyyMMdd-HHmm'
   docker compose exec postgres pg_dump -U indexd -Fc -f /tmp/indexd.dump indexd
   docker compose cp postgres:/tmp/indexd.dump ".\indexd-$d.dump"
   docker compose exec postgres rm /tmp/indexd.dump
   Get-Item ".\indexd-$d.dump" | Select-Object Name, Length
   ```

   Файл должен быть не пустым. Храните дамп вне папки с данными Docker.

2. **Остановка.** Даём indexd время завершить запись в базу блокчейна: если процесс оборвать посреди записи, база может повредиться.

   ```powershell
   docker compose stop -t 90 indexd
   ```

3. **Новая версия.** В `.env` замените `INDEXD_VERSION` на новую и скачайте образ:

   ```powershell
   docker compose pull
   ```

4. **Запуск и проверка.**

   ```powershell
   docker compose up -d
   docker compose logs -f indexd
   curl.exe -s -u ":<пароль admin>" http://127.0.0.1:9980/api/state
   ```

   В логе должны быть новая версия и `fork migration complete` (если у версии есть новые миграции), в ответе `api/state` — та же версия. Затем обновите страницу интерфейса клавишами **Ctrl+Shift+R**.

**Обновление с alpha.1.** Миграции форка (с 8 по 13) применяются за один запуск: в логе будет по одной строке `fork migration complete` на каждую миграцию, последняя с `forkVersion 13`. Первый запуск после обновления может занять чуть больше времени обычного.

**s3d.** Если вы используете s3d, обновите его после indexd до `v0.2.0-alpha.1`: новый s3d присылает замеры скорости, без них оценка Performance у хостов остаётся равной 1 (остальные оценки работают). Новый s3d с indexd старой версии работает как раньше.

Данные в томах (база цепи, PostgreSQL, конфиг) при обновлении сохраняются.

## 3. Переход с образа upstream на форк

Если у вас уже работает indexd из образа `ghcr.io/siafoundation/indexd`, перейти на форк можно на той же базе: это проверенный путь. Версия upstream, на которой основан форк, должна быть не новее вашей.

1. Сделайте дамп (раздел 2, шаг 1) и скопируйте `indexd.yml` в надёжное место.
2. Остановите indexd: `docker compose stop -t 90 indexd`.
3. В `docker-compose.yml` замените в сервисе `indexd` строку `image:` на `ghcr.io/mainquestion/indexd-smart-autopilot:<версия>`. Заодно проверьте строку портов admin: она должна быть вида `"127.0.0.1:9980:9980/tcp"`, а не `"0.0.0.0:…"`.
4. `docker compose up -d` и проверка, как в разделе 2, шаг 4. В логе будут миграции форка с первой по последнюю.

После этого **не возвращайтесь** на образ upstream: он не знает о таблицах форка. Для возврата восстанавливайте базу из дампа.

---

## 4. Что хранить отдельно

- recovery phrase кошелька;
- дампы базы (регулярно и перед каждым обновлением);
- файл `indexd.yml` из тома (содержит seed, храните как пароль): `docker compose cp indexd:/data/indexd.yml .\indexd.yml`;
- файл `.env`.

База блокчейна (`consensus.db`, около 90 ГБ) в резервные копии не нужна: она восстанавливается синхронизацией.

## 5. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `panic: page … already freed` в логе | Повреждена база блокчейна (`consensus.db`). Чаще всего данные лежали в папке Windows, проброшенной в контейнер. Используйте именованные тома; повреждённый `consensus.db` удалите, синхронизация начнётся заново |
| `docker compose pull` говорит `not found` или `denied` | Неверная версия в `.env` или образ в реестре ещё не опубликован |
| В Git Bash `pg_dump` падает на пути `/tmp/...` | Git Bash превращает пути в пути Windows. Выполните команду с `MSYS_NO_PATHCONV=1` или используйте PowerShell |
| `docker compose exec indexd sh` не работает | В образе нет оболочки. Файлы достаются командой `docker compose cp` |
| indexd не стартует после возврата на образ upstream | База уже мигрирована форком. Восстановите её из дампа |
| Admin недоступен с другого компьютера | Так и задумано: порт слушает только `127.0.0.1` |
| Место на диске заканчивается | Основное занимает база блокчейна; проверьте расположение виртуального диска Docker Desktop |
| Запрос `/api/wallet` не отвечает при работающих остальных | У нас это один раз прошло само после перезапуска (`docker compose stop -t 90 indexd`, затем `up -d`); причина не установлена |
