# Установлення й оновлення indexd Smart Autopilot у Docker

У цьому варіанті indexd працює у двох контейнерах: PostgreSQL 18 і сам indexd із готового образу. Вихідний код, Go та складання не потрібні: установлення й оновлення зводяться до кількох команд `docker compose`. Образ зібрано під Linux (`linux/amd64`), він займає близько 58 МБ.

Образ містить лише indexd. Шлюз s3d у Docker поки що не постачається: його, як і раніше, встановлюють окремо (див. [інструкцію для Windows](INSTALL-windows.md), розділ 9) і підключають до indexd за адресою з кроку 1.4.

Образ лежить у реєстрі GitHub: `ghcr.io/mainquestion/indexd-smart-autopilot:<версія>`. Версія образу — це версія upstream і короткий хеш коміту форку, наприклад `v0.2.0-alpha.1`. Перелік версій дивіться в розділі Releases репозиторію.

## Вимоги

- Docker Desktop (Windows, режим WSL2) або Docker Engine в Linux, Docker Compose v2.
- Близько 90 ГБ під базу блокчейну й щонайменше 60 ГБ вільного місця понад неї. Docker Desktop зберігає томи всередині власного віртуального диска; якщо системний диск невеликий, перенесіть цей диск у Docker Desktop: **Settings → Resources → Advanced → Disk image location**.
- Siacoin на гаманці indexd для оплати контрактів.
- Файли `docker-compose.yml` і `.env.example` з папки `docker` репозиторію.

## 1. Установлення з нуля

### 1.1 Підготовка

Створіть порожню папку, покладіть у неї `docker-compose.yml` і `.env.example`, потім скопіюйте приклад налаштувань:

```powershell
Copy-Item .env.example .env
notepad .env
```

У `.env` два обов'язкові значення: `POSTGRES_PASSWORD` — пароль бази даних (придумайте довгий) і `INDEXD_VERSION` — версія образу. Готових значень за замовчуванням немає: поки ви їх не задасте, compose відмовиться запускатися. Файл `.env` містить пароль, не публікуйте його й не синхронізуйте в хмару.

Папки з даними створювати не потрібно: compose використовує **іменовані томи** `indexd-data` і `postgres-data`, а Docker розміщує їх сам.

> Не замінюйте іменовані томи папками Windows (виду `D:\...:/data`). Коли ми спробували так, база блокчейну на прокинутій папці пошкодилася (`panic: page … already freed`). Причину не доведено, але іменовані томи надійніші: дані лежать у рідній файловій системі Linux усередині WSL2.

### 1.2 Завантаження образів

```powershell
docker compose pull
```

### 1.3 Recovery phrase

```powershell
docker compose run --rm indexd seed
```

Команда видає нову recovery phrase гаманця. Запишіть її на папері й не використовуйте фразу іншого вузла. Без неї не буде доступу ні до грошей, ні до контрактів.

### 1.4 Майстер налаштування

```powershell
docker compose run --rm -it indexd config
```

| Запитання майстра | Що відповісти |
|---|---|
| Recovery phrase | Фраза з попереднього кроку |
| Admin API password | Придумати — це пароль входу у вебінтерфейс |
| Application API advertise URL | `http://localhost:9982` — адреса, за якою застосунки на цьому комп'ютері підключатимуться до indexd (s3d, запущений на цьому самому комп'ютері) |
| Database host / port | `postgres` / `5432` — ім'я контейнера з базою |
| Database user / name | `indexd` / `indexd` |
| Database password | Той самий, що й `POSTGRES_PASSWORD` у `.env` |
| SSL mode | `disable` — база в сусідньому контейнері й назовні не публікується |

Адреси прослуховування залишаються такими, які пропонує майстер: контейнер сам слухає на `:9980` (admin), `:9981` (синхронізатор) і `:9982` (application), а назовні ці порти публікує compose.

Конфіг зберігається в томі `indexd-data` (`/data/indexd.yml`) і містить seed у відкритому вигляді. Не копіюйте його в публічні місця.

### 1.5 Запуск і перевірка

```powershell
docker compose up -d
docker compose logs -f indexd
```

У лозі з'являться версія образу, підключення до PostgreSQL, міграції (`migration complete`, `fork migration complete`) і `node started`. Вихід із перегляду логу — **Ctrl+C**, на роботу вузла він не впливає.

Перевірка версії:

```powershell
curl.exe -s -u ":<пароль admin>" http://127.0.0.1:9980/api/state
```

У відповіді мають бути ваша версія та `"os":"linux"`. Вебінтерфейс відкривається за адресою http://127.0.0.1:9980.

Спочатку indexd синхронізує блокчейн, це займає багато годин. Поки `synced` не стане `true`, а `scanHeight` не наздожене `syncHeight`, контракти не формуються (у лозі `waiting for wallet to be scanned`).

### 1.6 Що далі

Початкові налаштування (ціни, Wanted contracts, Placement, Scoring) такі самі, як під час установлення на Windows: розділ 8 [тієї інструкції](INSTALL-windows.md).

### Порти

| Порт | Призначення | Доступність за замовчуванням |
|---|---|---|
| 9980 | Admin API і вебінтерфейс | лише `127.0.0.1` |
| 9981 | Синхронізатор (зв'язок з іншими вузлами) | усі інтерфейси: інакше вузол приймає лише вихідні з'єднання |
| 9982 | Application API (для s3d та інших застосунків) | лише `127.0.0.1` |

Порти хоста можна змінити в `.env` (`INDEXD_ADMIN_PORT`, `INDEXD_SYNCER_PORT`, `INDEXD_APP_PORT`). Відкривати admin-порт у мережу не рекомендовано: через нього керується гаманець.

## 2. Оновлення до нової версії форку

Міграції схеми бази даних форку застосовуються вперед і **не відкочуються**. Повернутися на попередню версію можна лише з дампа, тому дамп робиться завжди.

1. **Дамп бази.** Його роблять усередині контейнера й копіюють назовні. Перенаправлення `>` у PowerShell псує двійкові файли, тому не користуйтеся ним:

   ```powershell
   $d = Get-Date -Format 'yyyyMMdd-HHmm'
   docker compose exec postgres pg_dump -U indexd -Fc -f /tmp/indexd.dump indexd
   docker compose cp postgres:/tmp/indexd.dump ".\indexd-$d.dump"
   docker compose exec postgres rm /tmp/indexd.dump
   Get-Item ".\indexd-$d.dump" | Select-Object Name, Length
   ```

   Файл не має бути порожнім. Зберігайте дамп поза папкою з даними Docker.

2. **Зупинка.** Даємо indexd час завершити запис у базу блокчейну: якщо процес урвати посеред запису, база може пошкодитися.

   ```powershell
   docker compose stop -t 90 indexd
   ```

3. **Нова версія.** У `.env` замініть `INDEXD_VERSION` на нову й завантажте образ:

   ```powershell
   docker compose pull
   ```

4. **Запуск та перевірка.** 

```powershell 
docker compose up -d 
docker compose logs -f indexd 
curl.exe -s -u ":<пароль admin>" http://127.0.0.1:9980/api/state 
```` 

У логу мають бути нова версія (`v0.3.0-rc.1`) та рядки `fork migration complete`, якщо у версії є нові міграції; у відповіді `api/state` та сама версія. Потім оновіть сторінку інтерфейсу клавішами Ctrl+Shift+R**. 

Якщо режим `Smart Active` або `Smart Shadow` включений, перегляньте рішення автопілота в `smart-autopilot.log` (він лежить у каталозі даних indexd) та на сторінці Hosts.

**Перед оновленням з v0.2.0-alpha.1 перевірте режим автопілота.** Нова версія в режимі Smart Active відразу починає виконувати план портфеля (формує і замінює контракти). Дізнайтеся поточний режим, поки працює **старий** контейнер:

```powershell
curl.exe -s -u ":<пароль admin>" http://127.0.0.1:9980/api/settings/smart
````

Якщо у відповіді `"mode":"active"`, переключіть його на сторінці **Scoring** у `Smart Shadow` (у новій версії поле називається **Autopilot Mode**), і лише потім оновлюйте образ. Слідкуйте за планом в `smart-autopilot.log`, потім знову увімкніть `Smart Active`. Аварійне гальмо: повернути `Smart Shadow`.

**Оновлення з v0.2.0-alpha.1.** Міграції форка з 14 по 17 застосовуються за один запуск: у лозі буде по одному рядку `fork migration complete` на кожну міграцію, остання з `forkVersion 17`. Перший запуск після оновлення може тривати більше звичайного часу. Міграції є незворотними, тому перед оновленням зробіть резервну копію бази PostgreSQL.

**Оновлення з v0.1.0-alpha.1.** Міграції форка з 8 по 17 застосовуються за один запуск, остання з `forkVersion 17`.

**s3d.** Якщо ви використовуєте s3d, оновіть його після indexd до `v0.3.0-rc.1`. Новий s3d надсилає виміри швидкості (для оцінки Performance) та звіти про витрати (колонки Σ на сторінці Contracts), а в режимі Smart Active розміщує нові завантаження по Smart Overall; режим він отримує від indexd, тому при Smart Active розміщення по Smart Overall почнеться протягом 10 хвилин після запуску. Новий s3d з indexd старої версії працює як раніше.

Дані в томах (база ланцюга, PostgreSQL, конфіг) під час оновлення зберігаються.

## 3. Перехід з образу upstream на форк

Якщо у вас уже працює indexd з образу `ghcr.io/siafoundation/indexd`, перейти на форк можна на тій самій базі: це перевірений шлях. Версія upstream, на якій ґрунтується форк, не має бути новішою за вашу.

1. Зробіть дамп (розділ 2, крок 1) і скопіюйте `indexd.yml` у надійне місце.
2. Зупиніть indexd: `docker compose stop -t 90 indexd`.
3. У `docker-compose.yml` замініть у сервісі `indexd` рядок `image:` на `ghcr.io/mainquestion/indexd-smart-autopilot:<версія>`. Заодно перевірте рядок портів admin: він має бути виду `"127.0.0.1:9980:9980/tcp"`, а не `"0.0.0.0:…"`.
4. `docker compose up -d` і перевірка, як у розділі 2, крок 4. У лозі будуть міграції форку з першої до останньої.

Після цього **не повертайтеся** на образ upstream: він не знає про таблиці форку. Для повернення відновлюйте базу з дампа.

## 4. Що зберігати окремо

- recovery phrase гаманця;
- дампи бази (регулярно й перед кожним оновленням);
- файл `indexd.yml` із тому (містить seed, зберігайте як пароль): `docker compose cp indexd:/data/indexd.yml .\indexd.yml`;
- файл `.env`.

База блокчейну (`consensus.db`, близько 90 ГБ) у резервні копії не потрібна: вона відновлюється синхронізацією.

## 5. Часті проблеми

| Симптом | Причина й рішення |
|---|---|
| `panic: page … already freed` у лозі | Пошкоджено базу блокчейну (`consensus.db`). Найчастіше дані лежали в папці Windows, прокинутій у контейнер. Використовуйте іменовані томи; пошкоджений `consensus.db` видаліть, синхронізація почнеться заново |
| `docker compose pull` повідомляє `not found` або `denied` | Хибна версія в `.env` або образ у реєстрі ще не опубліковано |
| У Git Bash `pg_dump` падає на шляху `/tmp/...` | Git Bash перетворює шляхи на шляхи Windows. Виконайте команду з `MSYS_NO_PATHCONV=1` або скористайтеся PowerShell |
| `docker compose exec indexd sh` не працює | В образі немає оболонки. Файли дістають командою `docker compose cp` |
| indexd не запускається після повернення на образ upstream | База вже мігрована форком. Відновіть її з дампа |
| Admin недоступний з іншого комп'ютера | Так і задумано: порт слухає лише `127.0.0.1` |
| Місце на диску закінчується | Основне займає база блокчейну; перевірте розташування віртуального диска Docker Desktop |
| Запит `/api/wallet` не відповідає, а решта працює | У нас це один раз минуло само після перезапуску (`docker compose stop -t 90 indexd`, потім `up -d`); причину не встановлено |
