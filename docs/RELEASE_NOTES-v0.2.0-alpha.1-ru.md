# indexd Smart Autopilot v0.2.0-alpha.1

Вторая альфа форка indexd: оценки хостов Smart Autopilot по четырём группам (скорость, ресурсы, экономика, риск), история цен и курса для них, группы колонок и меню View на странице Hosts.

| | |
|---|---|
| Версия сборки | `v0.6.1-7838380a` |
| База upstream | indexd v0.6.1 + исправление #1135 |
| Версия схемы форка | 13 (схема upstream 28) |
| Web UI | `feat/indexd-risk-score` |
| Компаньон | s3d Smart Autopilot v0.2.0-alpha.1 (`v0.2.1-ba6f8c9`) |

## Новое

**Оценки хостов Smart Autopilot (Shadow).** Оценки от 1 до 10 только **показываются**: на выбор хостов, формирование контрактов, паузы и миграции они **не влияют**. Считаются для *расчётного набора*: хосты пула (прошли фильтры цены и расположения) плюс хосты с активным контрактом; у остальных хостов оценки нет и в таблице стоит «—». Пересчёт раз в 10 минут и сразу при изменении настроек цен, расположения и списков хостов.

- **Performance (G2), скорость.** По реальным передачам s3d: загрузка и скачивание, окно 10 суток, оценка относительно 95-го перцентиля пула. s3d присылает замеры раз в минуту (`POST /hosts/speed`). Результат и сырые Мбит/с видны на странице Hosts.
- **Economics (G4), экономика.** Стоимость по профилю использования (ТБ хранения, ТБ загрузки и скачивания в месяц) плюс оценка залога (отношение залога к цене хранения и абсолютный залог); итог это минимум из оценок стоимости и залога. Цена загрузки включает временное хранение сектора (3 суток). Профиль и крутизна кривой `k` задаются на странице Scoring (по умолчанию 2 / 2 / 0.5 ТБ, `k = 9`).
- **Resources (G3), ресурсы.** Семь параметров в трёх блоках: объёмы данных (наши, свободное место, чужие), деньги и время (экспозиция, оценка стоимости восстановления, остаток срока контракта), доля потерянных секторов. Нормируется линейно по размаху расчётного набора.
- **Risk (G5), риск.** Нестабильность цены: каждое изменение цены хоста между соседними сканами (порог 5%, для ingress 50%, для залога только снижение) считается событием, если его не объясняет обратное движение курса SC/USD; чем больше событий за окно, тем ниже оценка. Окно по умолчанию 14 суток, настраивается на странице Scoring (`0` означает 14, не больше 120). У хоста с 0 или 1 точкой цены оценка 10.

**История для оценок.** Цены хоста (хранение, ingress, egress, залог) на каждом успешном скане, результаты сканов и курс SC/USD раз в 30 минут; хранение 120 суток, очистка раз в сутки. История копится с первого запуска этой сборки.

**Страница Hosts.**
- Меню **View**: показать и скрыть колонки по разделам.
- **Сворачиваемые группы колонок** Performance, Economics, Resources и Risk: в свёрнутом виде видна одна итоговая колонка группы, в развёрнутом вся группа; по умолчанию группы свёрнуты, состояние хранится в браузере.
- **Сортировка** по оценкам и отдельным параметрам групп (Order by и And sort); хосты без оценки в конце.

**Пауза по доступности.** Хост с низкой долей доступности (uptime) попадает в тот же механизм паузы, что и Smart Gouging Pause (период ожидания `Host grace period`).

**API.** `GET /hosts` получает поля `performance`, `economics`, `resources`, `risk` (отсутствуют у хостов вне расчётного набора) и новые ключи сортировки; новые настройки в `/settings/smart` (профиль Economics, окно Risk); `POST /hosts/speed` для замеров скорости от клиента. Форк-миграции 8–13, подробности в `FORK.md`.

## Изменения в интерфейсе

- Колонки цен Storage, Ingress, Egress и Collateral теперь входят в группу **Economics**, а Remaining Storage и Total Storage в группу **Resources**: при свёрнутой группе они не видны, раскрываются кнопкой группы рядом с меню View.
- В меню View эти колонки перенесены из раздела General в разделы своих групп.

## Исправления

- **Валюта в таблице Hosts.** Денежные значения (цены, залог, Exposure, Compensation) в таблице и на панели хоста пересчитываются, когда курс приходит позже списка хостов или меняется настройка валюты. Раньше они могли остаться в SC, пока не обновится сам список хостов.

## Обновление

1. Остановите s3d и indexd.
2. Сделайте дамп базы: `pg_dump -U postgres -h 127.0.0.1 -Fc -f indexd-before-alpha2.dump indexd` (в PowerShell используйте флаг `-f`, а не перенаправление `>`: оно портит бинарный дамп).
3. Замените бинарники и запустите indexd. В логе должно быть `fork migration complete {"forkTarget": 13, ...}`, затем запустите s3d.
4. При обновлении с alpha.1 миграции 8–13 применяются за один запуск. Новые настройки получают значения по умолчанию; поведение выбора хостов не меняется.
5. Новый s3d нужен для оценки скорости: со старым s3d остальные оценки работают, но Performance остаётся равной 1 (замеров нет). Новый s3d со старым (upstream) indexd получает `404` на `/hosts/speed` и перестаёт слать замеры.

Схема форка **не откатывается**: при необходимости восстановите базу из дампа.

## Известные проблемы и замечания

- **Альфа.** Проверено на одном узле Windows.
- **Оценки не влияют на решения.** Это режим Shadow: оценки для просмотра, выбор хостов и контрактов остаётся прежним.
- **Risk в первые дни.** История цен копится с первого запуска, поэтому у всех хостов сначала 0–1 точка и оценка 10 (колонка Price points показывает, сколько точек вошло в расчёт). Осмысленной оценка становится через 1–2 недели. Хосты сканируются примерно раз в сутки, поэтому в окне 14 суток не больше около 14 точек и краткосрочные скачки цены внутри суток не видны.
- **Скорость скачивания** в основном отражает отклик хоста: SDK читает часть сектора (около 100 КиБ на шард), поэтому Мбит/с скачивания сравнивают хосты между собой, но не равны пропускной способности канала. Загрузка измеряется по целым секторам.
- **Замеры скорости.** Присылает только s3d этого форка и только по успешным передачам, поэтому оценка слегка завышена для медленных хостов (в замер попадает победившая попытка). Для маршрута `/hosts/speed` нет ограничения по частоте (защита: подпись приложения, размер пакета до 1000 и проверки правдоподобия значений); значения присылает клиент и от подделки не защищены.
- **Нормализация Resources** по размаху набора чувствительна к выбросам: один хост с очень большим объёмом сжимает оценки остальных.
- **Economics.** Хост с нулевой итоговой ценой после скана получает лучшую оценку стоимости, как в renterd.
- Ссылка на версию в профиле узла ведёт на страницу релиза upstream, которой для сборок форка нет.
- Клиентские ограничения скорости соблюдает только s3d Smart Autopilot, остальные клиенты их игнорируют.
- Известные локальные падения тестов, не связанные с форком: `TestAppConnect` (часовой пояс), `TestAuthConnectRateLimit` и `TestScanTimeout` (время под нагрузкой и `-race`), `TestMigrationConsistency` в Windows-чекауте с CRLF (на LF проходит).
