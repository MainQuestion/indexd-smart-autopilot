# Встановлення indexd Smart Autopilot і s3d у Windows

Цей посібник описує нативне встановлення без Docker: спочатку PostgreSQL 18, потім indexd Smart Autopilot, після нього s3d Smart Autopilot і, за бажанням, rclone, який монтує сховище як звичайний диск у Провіднику. Кроки перевірено на реальному встановленні; можливі проблеми пояснено.

У прикладах використовуються наведені нижче шляхи й адреси. Їх можна змінювати, але послідовно в усіх кроках.

| Що | Шлях / адреса |
|---|---|
| indexd (програма й конфігурація) | `C:\IndexD` |
| Дані indexd | `D:\IndexD\data` |
| s3d (програма й конфігурація) | `C:\S3D` |
| Дані s3d (буфер завантажень) | `D:\S3D\data` |
| Порти indexd | admin `9980`, синхронізатор `9981`, application `9982` |
| Порти s3d | S3 `8000`, admin `8001` |

## Вимоги до встановлення

- 64-бітна Windows 10 або 11.
- PostgreSQL 18 для Windows.
- Щонайменше 60 ГБ вільного місця без урахування бази блокчейна (consensus); наразі вона займає близько 89 ГБ.
- Місце для буфера s3d: за замовчуванням до 10 ГіБ.
- Siacoin у гаманці indexd для оплати контрактів.
- Файли `indexd.exe` і `s3d.exe` з розділу [Releases](https://github.com/MainQuestion/indexd-smart-autopilot/releases).

## 1. Встановлення PostgreSQL 18

indexd зберігає всі дані — хости, контракти, слеби й налаштування — у PostgreSQL, тому починаємо з нього.

1. Завантажте інсталятор PostgreSQL 18 для Windows: https://www.postgresql.org/download/windows/ (збірка EDB).
2. В інсталяторі виберіть **PostgreSQL Server** і **Command Line Tools**; pgAdmin і Stack Builder не потрібні.
3. Задайте пароль суперкористувача `postgres` і запишіть його — він ще знадобиться.
4. Залиште порт **5432**.

Щоб перевірити роботу, відкрийте нове вікно PowerShell:

```powershell
Get-Service *postgres* | Select-Object Name, Status
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" --version
```

Служба `postgresql-x64-18` має бути в стані `Running`, а `psql` має показати версію 18.x.

## 2. Користувач і база даних indexd

indexd використовує окремого користувача бази даних. Створіть для нього **окремий** пароль — не той, що у `postgres`:

```powershell
$psql = "C:\Program Files\PostgreSQL\18\bin\psql.exe"
$env:PGPASSWORD = "<пароль postgres>"
& $psql -U postgres -h localhost -c "CREATE ROLE indexd WITH LOGIN PASSWORD '<пароль indexd>';"
& $psql -U postgres -h localhost -c "CREATE DATABASE indexd OWNER indexd;"
$env:PGPASSWORD = "<пароль indexd>"
& $psql -U indexd -h localhost -d indexd -c "SELECT current_user, current_database();"
Remove-Item Env:PGPASSWORD
```

Остання команда має повернути `indexd | indexd` — це означає, що користувача створено й він може ввійти до своєї бази. Якщо кирилиця у виводі відображається неправильно, не хвилюйтеся: це лише кодування консолі.

## 3. Обмеження мережевого доступу до PostgreSQL

Інсталятор EDB часто дозволяє підключення до PostgreSQL з усіх мережевих інтерфейсів. Оскільки indexd працює на цьому самому комп’ютері, краще закрити базу даних від мережі. Виконайте в PowerShell **від імені адміністратора**:

```powershell
$env:PGPASSWORD = "<пароль postgres>"
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -h localhost -c "ALTER SYSTEM SET listen_addresses = 'localhost';"
Restart-Service postgresql-x64-18
Remove-Item Env:PGPASSWORD
netstat -ano | Select-String ':5432'
```

Після перезапуску у виводі `netstat` мають залишитися лише `127.0.0.1:5432` і `[::1]:5432`.

## 4. Розміщення indexd

Створіть каталоги й помістіть `indexd.exe` з релізу до `C:\IndexD`:

```powershell
New-Item -ItemType Directory -Path C:\IndexD, D:\IndexD\data -Force | Out-Null
```

Зручно зберігати конфігураційний файл поруч із програмою. Вкажіть indexd, де він розташований:

```powershell
[Environment]::SetEnvironmentVariable('INDEXD_CONFIG_FILE', 'C:\IndexD\indexd.yml', 'User')
$env:INDEXD_CONFIG_FILE = 'C:\IndexD\indexd.yml'
```

> Каталог даних задайте в майстрі налаштування (наступний крок) і **не** задавайте одночасно змінну `INDEXD_DATA_DIR`. Змінна середовища має пріоритет над конфігурацією, тому шлях із файлу конфігурації буде мовчки проігноровано.

## 5. Початкове налаштування

Майстер налаштування поставить кілька запитань і створить `indexd.yml`:

```powershell
cd C:\IndexD
.\indexd.exe config
```

| Запитання майстра | Що вказати |
|---|---|
| Data directory | `D:\IndexD\data` |
| Recovery phrase (гаманець) | Згенерувати нову й записати на папері. Не використовуйте seed іншого вузла |
| Admin API password | Придумати пароль для входу у вебінтерфейс |
| Application API advertise URL | `http://localhost:9982` — адреса для підключення застосунків на цьому комп’ютері до indexd |
| Admin API Address | `127.0.0.1:9980` — обов’язково вкажіть адресу й порт; лише `9980` майстер не прийме |
| Application API Address | `127.0.0.1:9982` |
| Database user / name | `indexd` / `indexd` |
| Database password | Пароль **користувача indexd**. Якщо ввести пароль `postgres`, indexd не запуститься й покаже `SQLSTATE 28P01` |
| SSL mode | `disable` — локальний PostgreSQL працює без сертифіката, тому `verify-full` не підключиться |

Seed гаманця зберігається у `indexd.yml` у відкритому вигляді. Не публікуйте цей файл і не синхронізуйте його з хмарою.

Перевірити результат без показу секретів можна так:

```powershell
Get-Content C:\IndexD\indexd.yml | Select-String -NotMatch 'password|seed|recoveryPhrase|mnemonic|key:'
```

## 6. Прискорення синхронізації (необов’язково)

Повна синхронізація блокчейна з нуля триває багато годин. Її можна прискорити, використавши офіційний знімок бази ланцюга (bootstrap):

1. Якщо indexd уже запускався, зупиніть його клавішами **Ctrl+C** і дочекайтеся повідомлення `shutdown complete`.
2. Розпакуйте знімок і перевірте контрольну суму SHA-256, якщо її наведено на сторінці завантаження.
3. Перевірте назву файлу бази ланцюга в каталозі даних (`Get-ChildItem D:\IndexD\data`), перейменуйте його, наприклад, на `consensus.db.old`, а знімок розмістіть під початковою назвою.

Якщо знімок розташований на іншому диску, замість копіювання можна створити символічне посилання (cmd від імені адміністратора):

```cmd
mklink "D:\IndexD\data\consensus.db" "X:\путь\к\снимку\consensus.db"
```

> Файл бази ланцюга може використовувати лише один вузол. Не створюйте посилання на базу, яку вже відкрила інша програма.

## 7. Перший запуск

```powershell
cd C:\IndexD
.\indexd.exe
```

Окно PowerShell остаётся занятым, пока indexd работает. В логе вы увидите версию (`INFO indexd {"version": …}`), подключение к PostgreSQL, применение миграций схемы (`migration complete`, `fork migration complete`) и, наконец, `node started`. Строка `waiting for wallet to be scanned` означает, что indexd догоняет цепь, — это нормально.

Вебінтерфейс автоматично відкриється за адресою http://127.0.0.1:9980.

Чого очікувати протягом перших годин:

- **Спочатку список хостів порожній.** Хости з’являються в міру сканування; за замовчуванням сторінка показує лише придатні (usable).
- Одноразове **`indexer is offline, skipping scans`** означає короткочасний збій мережі. Якщо повідомлення повторюється, перевірте доступність `1.1.1.1:443`, `www.google.com:443` і `www.amazon.com:443`: indexd використовує ці адреси для перевірки інтернет-з’єднання.
- **Ваш власний хост у тій самій локальній мережі може не скануватися.** Маршрутизатор має підтримувати NAT loopback; indexd тут ні до чого.
- **Uptime нових хостів починається з 0.9 — порога придатності.** На новому встановленні один пропущений скан може вивести хост із пулу приблизно на тиждень. Перш ніж увімкнути систему, дайте indexd кілька днів накопичити історію.

## 8. Початкові налаштування

Поки систему вимкнено, задайте основні параметри:

1. **Configuration → Pricing.** Ліміти цін зберігання, завантаження та скачування (їх можна прив’язати до долара). Задавайте їх із запасом: нові контракти укладаються, лише якщо ціна хоста не перевищує буфер — за замовчуванням 80 % ліміту. Не встановлюйте **Min collateral** надто близько до застави дешевих хостів: за прив’язки до долара невелика зміна курсу може опустити хост нижче мінімуму, що призведе до блокування й перенесення всіх його даних.
2. **Configuration → Contracts.** **Wanted contracts** — не менше загальної кількості шардів (N) схеми s3d, бажано із запасом.
3. **Configuration → Placement.** Буфер ціни для нових контрактів, мінімальна відстань між хостами (GeoIP визначає місце розташування лише приблизно, до рівня міста), радіус і початкова точка.
4. **Scoring.** Режим Smart: `Shadow` лише записує в журнал, що зробила б пауза; `Active` ставить хост на паузу замість блокування, якщо перевищено ціну. Тут також налаштовуються ліміти швидкості міграцій і політика надлишковості для схем нижче стандартної.
5. **Hosts → Candidates.** Перегляньте, які хости indexd вибере за поточних налаштувань і чому інші відхилено.
6. **Wallet.** Поповніть гаманець за вказаною адресою.
7. Увімкніть систему перемикачем **System is currently disabled**.

За кілька хвилин на сторінці Contracts з’являться перші контракти, а в журналі — рядок `filtered new contract candidates` зі зведенням відбору.

## 9. s3d

s3d — це S3-сумісний шлюз: програми на кшталт rclone, Cyberduck або AWS CLI працюють із ним як зі звичайним S3, а він шифрує й кодує дані та розподіляє їх між хостами, з якими indexd має контракти.

### 9.1 Розміщення файлів

Помістіть `s3d.exe` з релізу в `C:\S3D` і підготуйте каталоги:

```powershell
New-Item -ItemType Directory -Path C:\S3D, D:\S3D\data -Force | Out-Null
[Environment]::SetEnvironmentVariable('S3D_CONFIG_FILE', 'C:\S3D\s3d.yml', 'User')
$env:S3D_CONFIG_FILE = 'C:\S3D\s3d.yml'
```

### 9.2 Ключ підключення застосунку

Застосунок може підключитися до indexd лише за ключем, виданим власником індексатора. У вебінтерфейсі indexd відкрийте розділ **Keys** і створіть **app connect key**. Він знадобиться за хвилину — у полі «App password».

### 9.3 Реєстрація s3d в indexd

```powershell
cd C:\S3D
.\s3d.exe login
```

- **Data directory** — `D:\S3D\data`.
- **Адреси** — S3 на `127.0.0.1:8000` (або `0.0.0.0:8000` для доступу з локальної мережі), admin на `127.0.0.1:8001`. Пароль admin обов’язковий.
- **Indexer URL** — `http://localhost:9982`. За замовчуванням указано `https://sia.storage`, тобто сторонній індексатор.
- **Recovery phrase** — залиште порожнім, s3d згенерує нову фразу. Обов’язково запишіть її: без неї неможливо розшифрувати дані.
- s3d покаже посилання на кшталт `…/auth/connect/…`. Відкрийте його в браузері, введіть app connect key і натисніть **Accept**. Запит діє недовго, тому створіть ключ заздалегідь і відразу підтвердьте підключення.

### 9.4 Користувач і S3-ключі

```powershell
.\s3d.exe users create <имя>
.\s3d.exe keys create <имя>
```

Друга команда покаже Access Key і Secret Key. Secret Key відображається **лише один раз** — збережіть його в менеджері паролів.

### 9.5 Схема надлишковості

В `C:\S3D\s3d.yml`, в разделе `sia`:

```yaml
    dataShards: 10      # K — шарды с данными
    parityShards: 20    # шарды чётности; всего N = K + parityShards
```

За замовчуванням використовується 10-of-30. Мінімально допустима схема для K = 10 — `parityShards: 15` (10-of-25). Схеми нижче стандартної, наприклад 3-of-5, приймаються лише за ввімкненої користувацької політики надлишковості в indexd (**Scoring → Redundancy**). Для кожного слеба потрібні N різних хостів, придатних для завантаження.

### 9.6 Запуск

```powershell
cd C:\S3D
.\s3d.exe
```

У журналі з’являться версія, рядок `erasure coding scheme accepted` із прийнятою схемою, `indexer transfer limits` і `server started`. Стан завантажень зручно переглядати з другого вікна командою `.\s3d.exe status`. Admin API s3d не призначений для перегляду у браузері; використовуйте `s3d status` або `curl.exe -u ":<пароль>" http://127.0.0.1:8001/stats/uploads`.

### 9.7 Доступ із локальної мережі

Якщо S3 слухає `0.0.0.0:8000`, дозвольте вхідні підключення в брандмауері. Мережа має бути позначена як **приватна** (`Get-NetConnectionProfile` → `NetworkCategory: Private`). Виконайте в PowerShell від імені адміністратора:

```powershell
New-NetFirewallRule -DisplayName "s3d S3 API (LAN)" -Direction Inbound -Protocol TCP -LocalPort 8000 -Profile Private -Action Allow
```

Не відкривайте цей порт в інтернет: S3 використовує звичайний HTTP без шифрування.

## 10. rclone: сховище як диск у Провіднику (необов’язково)

1. Установіть драйвер файлових систем WinFsp: `winget install WinFsp.WinFsp`. Без нього rclone не зможе змонтувати диск.
2. Створіть підключення (`rclone config` або вебінтерфейс rclone): тип **S3**, provider **Other**, ключі з кроку 9.4, endpoint `http://127.0.0.1:8000` (або IP комп’ютера із s3d), region `us-east-1`, `force_path_style = true`. Щоб бачити порожні папки, увімкніть `directory_markers = true`.
3. Назви бакетів можуть містити лише малі латинські літери, цифри й дефіс; підкреслення заборонено.
4. Монтуйте диск із **повним кешем**, інакше програми на кшталт Total Commander можуть повідомляти про помилки запису:

   ```powershell
   rclone.exe mount "<подключение>:" S: --vfs-cache-mode full --network-mode --cache-dir D:\rclone\cache
   ```

   Це також можна зробити через новий вебінтерфейс rclone: запустіть `rclone.exe gui --addr 127.0.0.1:5580 --api-addr 127.0.0.1:5572 --user gui --pass <пароль> --cache-dir D:\rclone\cache` і змонтуйте диск через API з параметром `vfsOpt='{"CacheMode":"full"}'`.

Кілька особливостей S3, які спочатку можуть здивувати:

- **У S3 немає справжніх папок.** «Папка» — це спільний префікс імен об’єктів, тому порожня папка не відображається, доки в ній немає файлу (або не ввімкнено `directory_markers`).
- **Переміщення — це копіювання та видалення.** Для великих файлів це може означати завантаження даних із мережі Sia.
- **Малі файли не передаються одразу.** s3d накопичує їх у буфері, доки не буде готовий цілий слеб. Примусово передати дані можна командою `s3d flush`.

## 11. Що зберігати окремо

Збережіть у надійному місці, не лише на цьому комп’ютері:

- seed гаманця indexd;
- recovery phrase s3d;
- S3-ключі користувачів;
- регулярні дампи бази indexd:
  ```powershell
  & "C:\Program Files\PostgreSQL\18\bin\pg_dump.exe" -U postgres -h 127.0.0.1 -Fc -f E:\Backup_indexd\indexd-<дата>.dump indexd
  ```
- резервні копії каталогу `D:\S3D\data`.

## 12. Оновлення

1. Зупиніть s3d, а потім indexd (**Ctrl+C** у відповідних вікнах).
2. Створіть дамп бази даних: міграції схеми під час оновлення незворотні, відновитися до попередньої версії можна лише з дампу.
3. Замініть `indexd.exe`, запустіть його й переконайтеся, що журнал містить нову версію та `fork migration complete`.
4. Замініть `s3d.exe` і запустіть його. Якщо разом із релізом оновлюється upstream-версія s3d, спочатку скопіюйте `D:\S3D\data`.
5. Примусово оновіть сторінку вебінтерфейсу клавішами **Ctrl+Shift+R**.

## 13. Поширені проблеми

| Симптом | Причина та рішення |
|---|---|
| indexd не запускается с `SQLSTATE 28P01` | В `indexd.yml` неверный пароль базы — чаще всего введён пароль `postgres` вместо пароля `indexd` |
| Мастер пишет `missing port in address` | Адрес нужно вводить вместе с хостом: `127.0.0.1:9980` |
| Свой хост в списке без цен и координат | indexd в той же локальной сети, роутер не поддерживает NAT loopback |
| Хост выпал из пула после отключения электричества | Uptime опустился ниже 0.9; хост вернётся примерно через неделю стабильной работы |
| Хост заблокирован с причиной `Collateral` | Залог хоста ниже минимума — часто из-за курса при привязке к доллару |
| `connection request expired` при `s3d login` | Создайте ключ подключения заранее и подтвердите запрос сразу |
| Admin API s3d в браузере отвечает `Unauthorized` | Браузер не передаёт пароль; используйте `s3d status` или `curl.exe -u` |
| `InvalidBucketName` при создании бакета | В имени бакета недопустимо подчёркивание |
| Ошибки записи на смонтированный диск | Диск смонтирован без `--vfs-cache-mode full` |
| Разделы интерфейса пропадают при переходах между меню | Старая версия — обновитесь до последнего релиза |
