Первый релиз-кандидат форка indexd. С выпуска v0.2.0-alpha.1 оценки хостов стали работающим автопилотом: один переключатель **Autopilot Mode**, **Smart Overall**, план портфеля с заменой худшего контракта, размещение загрузок и миграции по Smart Overall, **учёт расходов по хосту** на странице Contracts и новые правила формирования контрактов.

## Новое

**Autopilot Mode (один переключатель).** `Original` это поведение апстрима. `Smart Shadow`: Original продолжает работать, а Smart только считает решения и пишет их в `smart-autopilot.log`. `Smart Active`: Smart Autopilot управляет портфелем контрактов и размещает новые загрузки по Smart Overall. Значения в API остаются `original`, `shadow`, `active` (`/settings/smart`). Уже начатые паузы обслуживаются во всех режимах.

**Smart Overall.** Взвешенная сумма четырёх групповых оценок (Performance, Resources, Economics, Risk; веса 25/25/25/25, сумма 100) и порог замены (15 %) задаются на странице Scoring. Хосту без замеров скорости ставится временная оценка Performance (медиана хостов с контрактом и достаточным числом замеров). Оценка видна в таблице Hosts (`smartOverall`, `performanceImputed` в `GET /hosts`).

**План портфеля и его исполнение** (движок перенесён из renterd):
- План считается в Shadow и Active и пишется в лог; `GET /smart/portfolio-plan` отдаёт последний план и исходы исполнения.
- В Active **ADD** формирует новые контракты в каноническом порядке (Economics, при точной ничьей Risk) вместо случайного; радиус размещения остаётся группировкой.
- **REPLACE** (не чаще раза в 4 часа, одна замена за план): заменяется контракт с наименьшим Smart Overall, если кандидат лучше по Economics на порог и миграция выгодна (контракт без данных считается оправданным). Сначала формируется новый контракт, и только потом старый хост уходит на слив. Если замена пока не оправдана, контракт получает **экономическую паузу** (не больше одной, с оповещением); она снимается, когда подходящих кандидатов нет или Smart выходит из Active.
- Одновременно сливается только одна замена; слив считается законченным, когда у хоста не осталось наших секторов.

**Правила формирования контрактов (как в renterd).** Контракты хостов в Smart-паузе **занимают слоты** (Good + Paused, кроме паузы, у которой уже есть замена). Паузный хост заменяется, только если хороших контрактов меньше N+2 (N это число шардов схемы избыточности): при N+2 и больше никогда, ниже N сразу, между ними после тайм-аута паузы, не больше одной замены за проход, только в Smart Active. Это не даёт системе формировать лишние контракты, когда несколько хостов разом уходят в gouging-паузу. Предпросмотр кандидатов использует те же правила.

**Размещение загрузок и миграции по Smart Overall (Smart Active).** Новые сектора и приёмники миграции indexd идут на хосты с наибольшим Smart Overall, строго по порядку (при равенстве случайно); хост с отказами пропускается, хост без оценки идёт последним. Чтение не меняется. `GET /hosts` для приложений содержит `smartOverall` и `smartActive`; старые клиенты их игнорируют. В Smart Shadow выбор прежний, порядок Smart пишется в лог. s3d ведёт свой `smart-autopilot.log` рядом со своими данными.

**Учёт расходов по хосту.** Новая таблица (`host_spending_daily`, схема 17) фиксирует расходы по категориям: contract, storage, upload, download, verification, deletion; пополнение аккаунтов показывается отдельно как «Funded». Источники: сервер, мигратор и s3d (s3d присылает объём каждой успешной передачи, `POST /hosts/usage`; стоимость оценивается по ценам хоста и помечается `~`). `GET /host/{hostkey}/spending` возвращает итоги (за всё время и за 30 суток). История копится с первого запуска этой сборки.

**Страницы Hosts и Contracts.**
- Hosts: Usable показывает одну галку (непройденные проверки в подсказке), значки у цен становятся жёлтыми, если цена в пределах лимита, но выше предела формирования контракта, новая колонка **Accepted** (у хоста есть действующий хороший контракт, сортируется), один переключатель вида **Candidates | Usable + contracts | All**; по умолчанию показываются хосты с контрактом и хосты на Smart-паузе (параметр `involved` в `GET /hosts`), короткие подписи групп (Perf, Econ, Reso, Risk), ширины колонок по содержимому, заметно более быстрая отрисовка (подсказки монтируются при первом наведении, лимиты читаются один раз на таблицу), а при смене вида или фильтра страница сбрасывается на первую.
- Contracts: новые колонки **My Data** (по секторам), **Σ spent**, **Σ storage**, **Σ ingress**, **Σ egress** (за всё время; оценки помечены `~`), **Σ collateral**; меню View (Initial/Remaining Allowance и Used Collateral скрыты по умолчанию); панель показывает данные на хосте, расходы по категориям и источникам, передачи, оценки и причину паузы; у контракта хоста на паузе вместо Good показывается **Pause**.
- Приглушённые подписи и карта мира стали ярче (подписи имеют контраст не ниже 4,5:1 в обеих темах; карта в тёмной теме).
- Оценка скорости больше не сбрасывается в «нет данных», когда у хоста нет замеров в окне: остаётся последняя.
- Повторяющиеся строки журнала пишутся только при изменении состояния и не реже раза в 30 минут: план портфеля, решения Smart Gouging и пропущенные продления.

## Обновление

1. Остановите s3d и indexd.
2. Сделайте дамп базы: `pg_dump -U postgres -h 127.0.0.1 -Fc -f indexd-before-rc1.dump indexd` (в PowerShell используйте флаг `-f`, а не перенаправление `>`).
3. **Если Autopilot Mode стоит в `Smart Active`, сначала переключите его в `Smart Shadow`** (новая сборка в режиме Active сразу начинает исполнять план). Замените бинарники, запустите indexd (миграции 15–17 применяются за один запуск, `forkVersion 17`), затем s3d.
4. Понаблюдайте за планом в Shadow (`smart-autopilot.log`, `GET /smart/portfolio-plan`), затем включите Smart Active. Аварийный тормоз: вернуть Smart Shadow (экономические паузы снимутся на следующем проходе, начатый слив продолжится).
5. Новый s3d нужен для отчётов о расходах и для размещения Smart; старый s3d продолжает работать как раньше. Миграции не откатываются, при необходимости восстановите базу из дампа.

## Известные проблемы и замечания

- **Релиз-кандидат.** Проверено на одном узле Windows.
- Расходы клиентов (s3d) оценочные: неудавшиеся и прерванные передачи и миграции удалённых воркеров не считаются; «Funded» не равно расходу (часть остаётся на аккаунтах хостов).
- Контракт без данных всегда «стоит заменить» (переносить нечего): пока есть кандидаты лучше, такие контракты заменяются по одному за оптимизацию.
- Слитый контракт остаётся в списке до истечения, но он плохой, слот не занимает и не продлевается.
- Строгий порядок направляет новые данные на лучшие хосты по Smart Overall; оценка Resources падает по мере роста наших данных и со временем выравнивает порядок.
- Порядок кандидатов строится по Economics (Risk только при точной ничьей), поэтому хост с нестабильной историей цен может быть выбран, если его Economics лучшая.
- Бесконечный лимит цены (`MaxCurrency`) может переполниться при проверке новых контрактов; конечных лимитов это не касается.
- Известные локальные падения тестов: `TestAppConnect` (часовой пояс), `TestAuthConnectRateLimit` и `TestScanTimeout` (время), `TestMigrationConsistency` в чекауте с CRLF, `TestSmartPortfolioPlanAPI` (нестабилен).
