# indexd Smart Autopilot v0.1.0-alpha.1

Перша альфа-версія форку indexd.

| | |
|---|---|
| Версія збірки | `v0.6.1-9fd0bf52` |
| Базова upstream-версія | indexd v0.6.1 + виправлення #1135 |
| Версія схеми форку | 7 (upstream-схема 28) |
| Вебінтерфейс | `feat/indexd-speed-limits` |
| Супутній компонент | s3d Smart Autopilot v0.1.0-alpha.1 (`v0.2.1-a538024`) |

## Нове

- **Налаштування розміщення** (`/settings/placement`): допустиме відхилення ціни для нових контрактів 80–95 %, мінімальна відстань між хостами, радіус розміщення з режимами `prefer` / `strict`, опорна точка за IP або координатами.
- **М'який allowlist** і **окремі причини ручного/автоматичного блокування** (`/hosts/allowlist`, `/hosts/blocklist/detailed`).
- **Smart Gouging Pause** (`/settings/smart`): режими Original / Shadow / Active, параметри Keep Gouging Until Replacement і Allow Existing Data on Overpriced Contracts, тайм-аут призупинення 336 год, призупинення за співвідношенням застави й ціни, захисне відновлення Reed–Solomon, `smart-autopilot.log`, сповіщення, сторінка Scoring і стовпець Paused. Призупинення, розпочаті в режимі Active, тривають у будь-якому режимі.
- **Користувацька політика надлишковості** (`/settings/redundancy`): задається схемою кодування K/N і передається застосункам через `GET /account`.
- **Попередній перегляд кандидатів** (`GET /hosts/candidates`): пробний запуск вибору хостів для створення контрактів; режим Candidates на сторінці хостів показує карту та причини виключення.
- **Сортування**: Order by + And sort, сортування за Location і стовпцями кандидатів, стовпець Collateral.
- **Обмеження передавання** (`/settings/limits`): обмеження завантаження та вивантаження під час міграції; обмеження клієнтів на рівні квот і облікових записів передаються через `GET /account`.
- **Окремий ланцюжок міграцій форку**, незалежний від upstream-міграцій (`FORK.md`).
- **Інформація про версію** в журналі запуску, `indexd version`, `GET /api/state` та інтерфейсі.

## Виправлення

- Файли попереднього завантаження сегментів Windows-експорту Next.js тепер зводяться до потрібної структури, тому сторінки та стовпці форку не зникають під час клієнтської навігації.
- Нові стовпці таблиць, видимі за замовчуванням, додаються до збереженого стану таблиці.
- Блокування хоста, відсутнього в таблиці хостів, більше не завершується помилкою та не призводить до втрати причин блокування (також надіслано upstream як #1138).

## Оновлення

1. Зупиніть indexd (і s3d).
2. Створіть резервну копію бази даних: `pg_dump -U postgres -h 127.0.0.1 -Fc -f indexd-before-alpha1.dump indexd`.
3. Замініть виконуваний файл і запустіть програму. Очікується повідомлення `fork migration complete {"forkTarget": 7, ...}`.
4. Усі нові налаштування за замовчуванням зберігають поведінку upstream.

Схему форку не можна відкотити назад; за потреби відновіть базу з резервної копії.

## Відомі проблеми та примітки

- **Альфа-версія.** Перевірено лише на одному вузлі Windows.
- У режимах Smart **Shadow** та **Original** діє поведінка upstream: хост, що не відповідає обмеженням за ціною або заставою, блокується, а його дані мігруються. Фіксація ціни у фіатній валюті може спрацьовувати через незначні коливання курсу; таку поведінку спостерігали на хості, застава якого була на 0,6 % нижчою за зафіксований мінімум.
- Уже розпочатий прохід міграції завершується, навіть якщо хост тим часом розблокували.
- Посилання на версію в профілі вузла веде на сторінку upstream-релізу, якої для збірок форку не існує.
- Обмеження передавання даних клієнтів застосовуються лише в s3d Smart Autopilot; інші клієнти їх ігнорують.
- Відомі локальні помилки тестів, не пов'язані з форком: `TestAppConnect` (часовий пояс), `TestAuthConnectRateLimit` (часові умови під час запуску з `-race`).
