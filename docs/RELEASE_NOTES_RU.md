# indexd Smart Autopilot v0.1.0-alpha.1

Первая альфа-версия форка indexd.

| | |
|---|---|
| Версия сборки | `v0.6.1-9fd0bf52` |
| Базовая upstream-версия | indexd v0.6.1 + исправление #1135 |
| Версия схемы форка | 7 (upstream-схема 28) |
| Веб-интерфейс | `feat/indexd-speed-limits` |
| Сопутствующий компонент | s3d Smart Autopilot v0.1.0-alpha.1 (`v0.2.1-a538024`) |

## Новое

- **Настройки размещения** (`/settings/placement`): допуск по цене для новых контрактов 80–95 %, минимальное расстояние между хостами, радиус размещения с режимами `prefer` / `strict`, опорная точка по IP или координатам.
- **Мягкий allowlist** и **раздельные причины ручной/автоматической блокировки** (`/hosts/allowlist`, `/hosts/blocklist/detailed`).
- **Smart Gouging Pause** (`/settings/smart`): режимы Original / Shadow / Active, настройки Keep Gouging Until Replacement и Allow Existing Data on Overpriced Contracts, тайм-аут приостановки 336 ч, приостановка по соотношению залога и цены, защитное восстановление Reed–Solomon, `smart-autopilot.log`, оповещения, страница Scoring и столбец Paused. Приостановки, начатые в режиме Active, продолжаются при любом режиме.
- **Пользовательская политика избыточности** (`/settings/redundancy`): задаётся схемой кодирования K/N и передаётся приложениям через `GET /account`.
- **Предварительный просмотр кандидатов** (`GET /hosts/candidates`): пробный запуск выбора хостов для формирования контрактов; режим Candidates на странице хостов показывает карту и причины исключения.
- **Сортировка**: Order by + And sort, сортировка по Location и столбцам кандидатов, столбец Collateral.
- **Ограничения передачи** (`/settings/limits`): ограничения загрузки/скачивания при миграции; ограничения клиентов на уровне квот и учётных записей передаются через `GET /account`.
- **Отдельная цепочка миграций форка**, независимая от upstream-миграций (`FORK.md`).
- **Информация о версии** в журнале запуска, `indexd version`, `GET /api/state` и интерфейсе.

## Исправления

- Файлы предварительной загрузки сегментов Windows-экспорта Next.js теперь сводятся в нужную структуру, поэтому страницы и столбцы форка не пропадают при клиентской навигации.
- Новые столбцы таблиц, видимые по умолчанию, добавляются в сохранённое состояние таблицы.
- Блокировка хоста, отсутствующего в таблице хостов, больше не завершается ошибкой и не приводит к потере причин блокировки (также отправлено в upstream как #1138).

## Обновление

1. Остановите indexd (и s3d).
2. Сделайте резервную копию базы данных: `pg_dump -U postgres -h 127.0.0.1 -Fc -f indexd-before-alpha1.dump indexd`.
3. Замените исполняемый файл и запустите программу. Ожидается сообщение `fork migration complete {"forkTarget": 7, ...}`.
4. Все новые настройки по умолчанию сохраняют поведение upstream.

Схему форка нельзя откатить назад; при необходимости восстановите базу из резервной копии.

## Известные проблемы и примечания

- **Альфа-версия.** Проверено только на одном узле Windows.
- В режимах Smart **Shadow** и **Original** действует поведение upstream: хост, не проходящий ограничения по цене или залогу, блокируется, а его данные мигрируются. Фиксация цены в фиатной валюте может срабатывать из-за небольших колебаний курса; такое поведение наблюдалось на хосте, у которого залог оказался на 0,6 % ниже зафиксированного минимума.
- Уже начавшийся проход миграции завершается, даже если хост тем временем разблокировали.
- Ссылка на версию в профиле узла ведёт на страницу релиза upstream, которой для сборок форка не существует.
- Ограничения передачи данных клиентов применяются только s3d Smart Autopilot; другие клиенты их игнорируют.
- Известные локальные ошибки тестов, не связанные с форком: `TestAppConnect` (часовой пояс), `TestAuthConnectRateLimit` (временные условия при запуске с `-race`).
